# Защита: 7–10 минут

1. Задача: по вопросу студента найти документ с подходящим ответом и показать источник. Это retrieval chatbot, а не модель с гарантией знания любых фактов.
2. Покажите запуск `python3 start.py`, 604 карточки и фильтры. Объясните, что 96 вариантов формулировок не считаются отдельными фактами.
3. Диалог: стоимость обучения → уточнение → бакалавриат. Затем другая тема: интернет в общежитии. Затем вопрос без данных: личные оценки или будущая стоимость.
4. Архитектура: оба интерфейса обращаются к одному Python API. SQLite хранит корпус, источники, ключевые слова и результаты. Контекст беседы находится в памяти клиента.
5. Поиск: baseline, BoW/TF-IDF, BM25, E5. RRF объединяет позиции, cross-encoder оценивает пары вопрос–документ. Приоритет источника меняет порядок, но не превращает нерелевантный фрагмент в уверенный ответ.
6. Предобработка: показать строку CSV со stemming NLTK и лемматизацией spaCy. Объяснить, почему для embeddings используется исходный текст, а не стеммы.
7. Оценка: открыть таблицу измерений и одну реальную ошибку. P@3 отличается от Hit@3. Маленькая AI-assisted выборка не доказывает качество на всех вопросах.
8. SQL: показать ER-диаграмму, запрос с JOIN/HAVING и `latest_method_results` с ROW_NUMBER. Открыть соответствующий CSV, выгруженный в Pandas.
9. Ограничения: неактуальные исходные ответы, неполная разметка, отсутствие персональных/оперативных данных. Вклад участников заполнить по фактически выполненной работе.
